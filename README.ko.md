# Satellite PCB Agent Guide

AI 에이전트와 위성용 회로 기판을 설계할 때, 부품을 선택하는 모든 판단에 데이터시트 근거를 연결하는 가이드입니다.

이 저장소는 진입점인 `AGENTS.md`, 상세 검토 기준, 재사용할 수 있는 기록 템플릿을 제공합니다. 엔지니어와 에이전트가 설계 전 과정에서 요구사항, 부품 사양, 실제 회로 조건, 검증 결과를 함께 관리하도록 돕습니다.

**BOM 후보를 평가할 때와 선정한 부품의 회로·PCB 적용을 검토할 때, 모든 칩의 제조사 데이터시트를 직접 확인합니다.** 정확한 부품, 조건, 근거, 여유도, 판정을 기록한 뒤 선정을 확정합니다.

## 내 프로젝트에 적용하기

저장소를 복제합니다.

```bash
git clone https://github.com/sel00000/satellite-pcb-agent-guide.git
```

1. [AGENTS.md](AGENTS.md), `docs/`, `templates/`를 PCB 프로젝트의 최상위 폴더에 함께 복사합니다. 기존 지침이나 폴더가 있다면 내용을 확인해 병합합니다. `AGENTS.md`를 읽는 에이전트를 사용하거나, 이 파일을 프로젝트 지침으로 명시해 제공합니다.
2. [프로젝트 요구사항 템플릿](templates/project-requirements.md)을 작성합니다. 아직 모르는 입력값은 `TBD`, 그 값에 의존하는 판정은 `UNVERIFIED`로 남깁니다.
3. 부품 후보와 사용 조건별로 [부품 검토 템플릿](templates/component-review.md)을 `reviews/components/`에 복사합니다. 제조사 원문은 `evidence/datasheets/` 같은 프로젝트 폴더에 버전과 함께 보관합니다.
4. [BOM 검토 대장](templates/bom-review.csv)에 후보를 추가하고 검토 기록을 연결합니다. 제공하는 CSV에는 열 이름만 들어 있습니다. 검토가 진행 중이어도 후보 목록은 작성할 수 있지만, BOM 확정에는 적용되는 검토 항목의 완료가 필요합니다.
5. 중요한 설계 선택에는 [설계 판단 템플릿](templates/design-decision.md)을 `reviews/decisions/`에 복사해 사용합니다. [단계별 완료 기준](docs/space-board.md)에 따라 부품 검토, 설계 검토, 제작 승인, 비행 승인을 구분합니다.

에이전트에는 다음과 같이 요청할 수 있습니다.

```text
AGENTS.md에 따라 이 후보 BOM을 검토해줘. 정확한 MPN별로 제조사
데이터시트를 읽고, 실제 회로 조건에서 DS-00부터 DS-06까지 평가한 뒤
서로 연결된 부품 검토 기록을 작성해줘. 근거가 부족한 항목은
UNVERIFIED로 표시하고 해결에 필요한 자료를 적어줘. 중요한 선택에는
해당하는 위성 환경 기준과 설계 판단 절차도 적용해줘.
```

이 패키지는 지침과 템플릿으로 구성되어 있습니다. 프로젝트의 에이전트가 지침을 따르고 필요한 문서와 도구에 접근할 수 있어야 합니다. 저장소 자체가 데이터시트를 자동으로 가져오거나 검토 판정을 강제하지는 않습니다.

## 부품 검토마다 확인할 여섯 가지

먼저 **DS-00: 식별과 추적성**을 확인합니다. 제조사, 실제 주문 가능한 정확한 부품 번호(MPN), 접미사, 패키지, 핀 배치, 적용 등급을 대조합니다. 문서 개정 번호와 관련 페이지, 표, 그림, 각주를 기록합니다.

| ID | 검토 항목 | 검토로 확인할 내용 |
|---|---|---|
| DS-01 | Absolute Maximum Ratings — 절대 최대 정격 | 정상 상태와 과도 상태의 스트레스가 적용 한계 안에 있는지 확인합니다. 절대 최대 정격을 정상 동작 목표로 삼지 않습니다. |
| DS-02 | Recommended Operating Conditions — 권장 동작 조건 | 전원, 입력, 온도, 주파수, 전원 시퀀스가 명시된 동작 조건과 프로젝트 제한을 만족하는지 확인합니다. |
| DS-03 | Electrical Characteristics — 전기적 특성 | Min/Typ/Max 값과 시험 조건이 실제 회로에서 필요한 성능을 뒷받침하는지 확인합니다. 대표값(Typ)은 보증값이 아닙니다. |
| DS-04 | Thermal Characteristics — 열 특성 | 부품 손실, 열 전달 경로, 경계 조건, 접합 온도를 근거로 필요한 열적 여유가 있는지 확인합니다. |
| DS-05 | Timing Characteristics — 타이밍 특성 | 셋업·홀드, 전파 지연, 상승·하강, 기동·종료, 보호 응답이 해당 최소·최대 요구조건을 만족하는지 확인합니다. |
| DS-06 | Peak / Continuous Current, SOA — 피크·연속 전류와 안전 동작 영역 | 연속·RMS·피크·펄스 스트레스를 지속 시간, 반복 조건, 온도, 동시에 걸리는 전압과 함께 평가합니다. |

전력 반도체, 수동소자, 커넥터, 연결부에도 해당하는 검토를 적용합니다. 같은 MPN은 원문을 공유할 수 있지만, 전원·부하·타이밍·냉각 조건이 다르면 각각 평가합니다. 자세한 기준은 [데이터시트 검토 문서](docs/datasheet-review.md)에 있습니다.

## 위성 환경까지 검토하기

[위성 보드 기준](docs/space-board.md)은 임무 요구사항과 표준, 디레이팅과 수명 말기 조건, 진공에서의 열 전달, 방사선과 복구, 전원과 고장 영향, 재료와 추적성, 검증 계획을 다룹니다.

한계값과 합격 기준은 실제 임무에 맞춰 정합니다. 보드 기능, 궤도, 수명, 전원, 부하, 열 인터페이스, 방사선 환경, 부품 등급, 적용 표준은 프로젝트에서 채워야 할 입력입니다. 이 가이드는 모든 임무에 공통으로 쓸 선량, 디레이팅 계수, 시험 횟수를 제시하지 않습니다. 임무별 적합성은 근거가 확보될 때까지 `UNVERIFIED`로 남깁니다.

## 근거를 통해 설계 판단 개선하기

[설계 판단 절차](docs/design-reasoning.md)는 *ScientistTwo*의 가설·실험·비판·개선 구조를 다음 여덟 단계로 적용합니다.

1. 문제, 한계, 합격 기준을 정의합니다.
2. 재현 가능한 기준 설계를 확보합니다.
3. 대안과 검증 가능한 가설을 세웁니다.
4. 범위를 명시해 후보를 선별합니다.
5. 전체 요구 범위와 실제 구현의 일치 여부를 검증합니다.
6. 원인과 각 변경의 기여를 분석합니다.
7. 검토 지적 사항을 추가 근거로 해결합니다.
8. 다시 평가한 뒤 채택 여부와 판단을 기록합니다.

새로움보다 요구사항과 신뢰성을 우선합니다. 실패 기록을 보존하고, 같은 조건에서 변경 전후를 비교하며, 검토 예산이 소진되어도 미해결 항목은 `UNVERIFIED`로 유지합니다. 어떤 개념을 옮겼는지는 [출처 기록](docs/sources.md#s9)에 명시했습니다. 하드웨어 검토에 맞게 구성한 절차이며, ScientistTwo를 설치하거나 논문의 성능을 재현하거나 여러 에이전트를 자동으로 실행하는 기능은 포함하지 않습니다.

## 판정과 근거 연결하기

| 상태 | 의미 |
|---|---|
| `PASS` | 기록된 범위와 조건 안에서 해당 검토를 뒷받침하는 근거가 있습니다. |
| `FAIL` | 적용되는 요구사항을 충족하지 못한다는 근거가 있습니다. |
| `UNVERIFIED` | 필요한 요구사항, 원문 자료, 분석, 검증이 부족하거나 변경으로 기존 근거가 유효하지 않습니다. |
| `NOT_APPLICABLE` | 해당 검토가 적용되지 않으며, 그 이유와 근거를 기록했습니다. |

**필수 항목에 `FAIL`이나 `UNVERIFIED`가 남아 있으면 부품이나 그에 의존하는 설계를 확정하지 않습니다.** 독립적인 조사, 계산, 초안 작성은 계속할 수 있습니다. 부품, 문서, 회로, PCB, 펌웨어, 부하, 클록, 열 경로가 바뀌면 영향을 받는 판정을 다시 검토합니다.

제조사 사실, 가정, 계산, 시뮬레이션, 측정, 승인을 구분합니다. 검토의 `PASS`, ERC/DRC 결과, 상온 시험 결과만으로 비행 승인이 성립하지 않습니다. 비행 사용 승인은 프로젝트의 지정 책임자와 필요한 적격성 검증 근거에 따라 결정합니다.

## 범위와 출처

위성 PCB 프로젝트에 재사용할 수 있는 문서 패키지입니다. 특정 보드 기능, 실제 BOM, 회로, 완료된 하드웨어 적격성 검증 결과는 제공하지 않습니다.

[출처 문서](docs/sources.md)에 제조사, NASA, ECSS, 연구 문헌 링크와 실제 검토 범위를 정리했습니다. 패키지 작성에 사용한 사용자 제공 자료도 기록했으며, 원본 첨부파일은 이 저장소에 배포하지 않습니다.

개선을 제안할 때는 해당 규칙과 사용 상황, 뒷받침하는 출처, 검토 기준에 미치는 영향을 함께 적어 주세요. 공통 설명을 수정할 때는 영어와 한국어 README의 내용도 함께 맞춰 주세요.
